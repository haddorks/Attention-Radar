I wanted to take the emotion out of trading.

So I designed a system that makes the decisions in the same way every time, then built the data, the logic and the AI workflow to run it. Attention Radar is that system.

The problem

Picking trades by hand was not working for me.

Emotion decided the exits

I found it hard to close losing trades. The decision that mattered most was the one I was worst at making under stress.

Too much to watch, too little time

There are over 200 stocks in the options market, and the moves that matter happen in the first 45 minutes after the open. No one can watch that by eye.

Other people’s calls teach nothing

Following tips gives no method to improve. I wanted a system I understood end to end and could change.

Why I built it this way

Each design choice answers one of those problems.

Fixed rules instead of gut feel

Entry, selection and exit rules are written down before the market opens, so the emotional step is removed from the loop.

My own system, built from scratch

Building every layer myself meant I knew why each decision was made, and could change one part without breaking the rest.

A lab kept apart from the live system

New ideas were explored in a separate research area, so an unproven experiment could never quietly change the rules that were running.

An exit advisor and a hard deadline

The exit logic advises and never closes a position by itself. A hard close at 15:00 covers the day, because resting stop orders are cancelled at 15:15.

Every idea checked against a baseline

Before trusting a rule, I compared it with random behaviour on the same data, so I knew what the system was really doing.

Where it is headed

An AI partner for the work.

The longer aim is an assistant I can work with every day: one that holds the full project context, tests ideas with me and keeps me honest. This project is how I am learning to build and manage that kind of system.

How I built it

A pipeline from raw data to a managed position.

DataIngestMinute bars for 205 NSE instruments and 278K exchange filings, through resumable API downloaders.
DetectScanRule gates and a ranking layer score every stock in the opening window of the market.
SelectChoose the contractReads the live option chain to pick the strike, with premium, delta and open interest.
ProtectManage riskStop and target planner, trailing logic and a hard deadline that closes positions on time.
ReviewLearnEvery decision is logged with real option-chain context, then replayed and studied.

Two codebases kept apart on purpose: a rule-based screener with frozen rules, and a separate research area for ideas that were not yet proven. That way an experiment could not quietly change the system that was running.

How I ran it

I treated the AI like a team member that needs good management.

A written spec

A 788-line, version-controlled file loaded into every AI session: the goal, the architecture, the rules that are frozen and the mistakes not to repeat.

Two agents, clear roles

One agent for strategy and judgement with full project history. One for code, debugging and tests on real data. The spec is the shared memory between them.

A morning routine

Each trading day starts with a script that refreshes the API credentials and re-reads the rules to the agent, because both silently go stale.

Review and challenge

I questioned the agent’s output, cross-checked it against a second model, and fixed the instruction file when the agent misread it.
